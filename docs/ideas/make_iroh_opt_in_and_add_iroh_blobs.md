altough it is unrealistic to use something else then iroh, we introduce some limitations by giving the user a native language-only SDK. for example it is hard to install own custom protocols. to accomondate for these use cases we treat iroh as a pluggable module for rocky which itselfs comes with extensions like a iroh-blobs api. A developer can than plugg these extensions into each other when they have the need for it. technically the iroh module supports creating own extensions as well that can than be consumed like a first-party extension. the iroh-blobs extension should use exactly that mechanism
